# Лабораторная работа 4. API списка и HomeBloc

Дисциплина: кроссплатформенные средства разработки программного обеспечения. Учебная тема — «Книга рецептов», вариант 3.

**Это самостоятельный репозиторий только ЛР 4.** Для проверки не требуется скачивать остальные лабораторные. Предыдущие компоненты включены в том объеме, в котором нужны текущему этапу.

## Что выполнено

**Первый сетевой запрос.** Список получает GET /recipes?limit=10 через Dio, репозиторий и HomeBloc. Подробный экран пока использует локальный набор. Метода getContentById и ContentBloc в этом репозитории нет.

На защите: Модель и генерация JSON, HomeLoad, четыре состояния, getContent, отображение ошибки и повторная загрузка.

## Запуск

Нужен Flutter SDK с Dart >= 3.10. Исходная реализация подготовлена на Flutter 3.47.9 / Dart 3.13.7; точные разрешенные зависимости находятся в `pubspec.lock`.
Установите SDK и добавьте `flutter/bin` в PATH. Для Windows нужны Visual Studio Build Tools с C++; для Web — браузер Chrome или Edge.
Клонируйте проект в путь без кириллицы, например `C:/projects/flutter-lab-04`.

```powershell
flutter pub get
flutter run -d windows
# или Web
flutter run -d chrome
```

Стандартная точка входа — `lib/main.dart`. В VS Code также есть одна конфигурация Run and Debug именно для этой работы.
На Windows для папки с кириллицей можно использовать `./run-lab.ps1`: скрипт создает короткую ASCII-ссылку, печатает Project build path и запускает только этот этап.
Если PowerShell блокирует ps1, используйте стандартные команды Flutter из ASCII-пути; изменять политику выполнения не требуется.

Именованная точка входа из отчета сохранена: `lib/main_lab4.dart`. Файл `main.dart` вызывает ее. Других учебных этапов здесь нет.

Для каталога нужен интернет. DummyJSON не требует токена. Изображения загружаются отдельно; сбой фотографии не скрывает текст рецепта. Сетевая ошибка данных показывается явно, без замены локальным каталогом.

Статические данные и изображения входят в `assets/`. Их пути объявлены в pubspec.yaml. Модель и сгенерированный JSON-код включены, поэтому для первого запуска ничего генерировать вручную не требуется.

## Проверки

```powershell
flutter analyze
flutter test --reporter expanded
flutter test integration_test/app_test.dart -d windows
flutter build web --release --no-wasm-dry-run
```

Нативный интеграционный тест относится только к этому этапу. Он проверяет реальное окно Flutter и сохраняет настоящие кадры в `test_screenshots/`; эта папка и сборочные кэши исключены из Git.
Тесты репозитория и BLoC, когда они есть, используют управляемые ответы для воспроизводимой проверки ошибок. Проверка HTTP в нативном тесте использует настоящий Dio.

При изменении модели заново выполните `dart run build_runner build`. Версия build_runner закреплена из-за совместимости с test_api исходного Flutter SDK.

Результаты проверки выделенного проекта записаны в `verification/`. Исходные исторические снимки в отчете и дополнительные материалы относятся к общему учебному проекту; подписи, показывающие будущие этапы, сохранены явно.
